# שיבוץ מקומות לימים נוראים

מערכת לניהול ושיבוץ מקומות ישיבה בבית הכנסת — מפה ויזואלית, חשבונות משתמשים,
ושמירה בענן. רצה כולה על **Cloudflare Worker** אחד: אין שרת משלך, אין מכונה שצריכה
להיות דלוקה, ואין תשלום בשימוש רגיל.

| רכיב | מה זה |
|---|---|
| `index.html` | כל האפליקציה — HTML, CSS ו-JS בקובץ אחד, ללא ספריות חיצוניות |
| `worker/src/index.js` | ה-Worker: מגיש את הדף וגם את ה-API (חשבונות, מפות, ניהול) |
| D1 | מסד נתונים מנוהל של Cloudflare (SQLite). הטבלאות נוצרות אוטומטית |

---

## מודל המשתמשים

- **כל מי שנרשם פותח בית כנסת משלו** ונעשה הבעלים שלו.
- הבעלים יכול **לצרף גבאים נוספים** לאותו בית כנסת באמצעות קוד הזמנה, ולהחליט לכל
  אחד אם הוא עורך או צופה בלבד.
- **משתמש רואה אך ורק את הנתונים של בית הכנסת שלו.** אין גישה בין בתי כנסת.
- **מנהל-על** (המייל שמוגדר ב-`SUPER_ADMIN_EMAIL`) רואה את כל בתי הכנסת והמשתמשים,
  ויכול להחליף סיסמה לכל אחד.
- **מצב אורח** — אפשר לעבוד בלי חשבון כלל. הנתונים נשמרים בדפדפן בלבד, עם ייצוא
  וייבוא ידניים. בהרשמה מוצע להעלות את נתוני האורח לחשבון החדש.

---

## התקנה — הכל מהדפדפן, בלי להתקין כלום

### 1. יצירת מסד הנתונים
בלוח הבקרה של Cloudflare: **Workers & Pages → D1 → Create database**
בשם `beit-midrash-seating`. העתק את ה-**Database ID** שמוצג.

> אין צורך להריץ שום SQL — הטבלאות נוצרות אוטומטית בעלייה הראשונה של ה-Worker.

### 2. עדכון קובץ ההגדרות
ערוך ב-GitHub את `worker/wrangler.toml`:

```toml
database_id = "כאן ה-Database ID שהעתקת"

[vars]
SUPER_ADMIN_EMAIL = "כאן המייל שלך"
```

### 3. יצירת מפתח API
Cloudflare → **My Profile → API Tokens → Create Token** → תבנית
**Edit Cloudflare Workers**. ודא שהרשאות ה-Token כוללות גם **D1 → Edit**.
העתק את ה-Token (הוא מוצג פעם אחת בלבד).
את ה-**Account ID** מוצאים בעמוד הראשי של Workers & Pages.

### 4. הוספת הסודות ל-GitHub
בריפו: **Settings → Secrets and variables → Actions → New repository secret**

| שם | ערך |
|---|---|
| `CLOUDFLARE_API_TOKEN` | ה-Token מהשלב הקודם |
| `CLOUDFLARE_ACCOUNT_ID` | ה-Account ID |

### 5. העלאה
לשונית **Actions** → `Deploy to Cloudflare Workers` → **Run workflow**.
מכאן והלאה כל שינוי שנדחף ל-`main` מתעדכן אוטומטית.

### 6. הרשמה
היכנס לכתובת שה-Action מדפיס (`https://beit-midrash-seating.<שם>.workers.dev`)
והירשם ראשון — החשבון שלך יקבל אוטומטית הרשאת מנהל-על.

<details>
<summary>העלאה מהמחשב במקום מ-GitHub (אופציונלי)</summary>

דורש Node.js 20 ומעלה:

```bash
cd worker && npm install && npx wrangler login && npm run deploy
```
</details>

## מבנה המקומות

| אזור | תיאור | מספור |
|---|---|---|
| בית המדרש | לרוחב. ארון קודש בחזית, בימה במרכז | שורה א׳, ב׳, ג׳… |
| שולחנות צד ימין | 4 מקומות בכל שולחן | 1 · 2 · 3 · 4 |
| סטנדרים במרכז | שני טורים, 2 מקומות בכל סטנדר | 1 · 2 |
| שולחנות צד שמאל | 4 מקומות בכל שולחן | 1 · 2 · 3 · 4 |
| עזרת נשים | לאורך, בצד שמאל, מופרדת במחיצה. 11 שולחנות של 3 מקומות | שולחן א׳, ב׳, ג׳… |

לחיצה על מקום פותחת חלון עריכה: תואר לפני (`ה"ה`), שם פרטי, שם משפחה,
תואר אחרי (`הי"ו`), טלפון והערות, עם כפתורי **שמירה · שולם · פינוי מקום · ביטול**.
צבעי המפה: 🟢 שולם · 🔴 תפוס וטרם שולם · ⬜ פנוי.
על המפה מוצגים שם פרטי ומשפחה בלבד; התארים מופיעים ביצוא.

### שינוי מבנה האולם
בראש בלוק ה-`<script>` נמצא אובייקט `CONFIG` עם מספר השורות, המקומות בכל שולחן,
מיקום הבימה ומספר שולחנות עזרת הנשים. המספרים הנוכחיים זמניים.

## יצוא

**מפה (PDF / הדפסה)** — לרוחב, עם **התאמה אוטומטית לעמוד יחיד**:
היקף (בית מדרש · עזרת נשים · מפה מלאה), מועד (ראש השנה בגווני חום־שמנת־זהב,
או יום כיפור בזהב מלכותי ולבן), הצגת תארים, וצביעה לפי סטטוס תשלום.
הכותרת: `שיבוץ מקומות [המועד] בית מדרש תפארת יהודה`.

> בחלון ההדפסה של הדפדפן יש לבחור **שמירה כ-PDF** ולסמן **גרפיקת רקע**,
> אחרת ה-PDF ייצא לבן.

**טבלה (Excel)** — שלוש עמודות: `שורה / שולחן` · `מספר מקום` · `שם מלא כולל תארים`
(לדוגמה `שורה א׳ — צד ימין | 1 | ה"ה אברהם כהן הי"ו`), עם ייצוא נפרד לכל אזור.

## שמירה — ארבע שכבות

1. **שמירה בענן** — בחשבון, כל שינוי עולה לשרת תוך פחות משנייה. החיווי בסרגל העליון
   מראה "נשמר בענן HH:MM". אם הרשת נופלת, הנתונים נשמרים במחשב ועולים כשהיא חוזרת.
2. **טיוטה תוך כדי הקלדה** — מה שמוקלד בחלון העריכה נשמר עוד לפני לחיצה על "שמירה".
   אם החלון נסגר באמצע, בפתיחה הבאה מוצע להמשיך מאותה נקודה.
3. **אזהרה לפני סגירה** — סגירת לשונית, "ביטול" או Esc עם שינוי פתוח מבקשים אישור.
4. **היסטוריית גרסאות** — בענן נשמרות 30 הגרסאות האחרונות (במצב אורח 25 מקומיות),
   עם שעה, מספר משובצים ושם העורך. ניתן לחזור לכל אחת מהן — כולל ביטול "איפוס הכל".

**עריכה במקביל:** אם שני גבאים עורכים יחד, השרת מזהה התנגשות ומציע לבחור בין הגרסה
שבשרת לגרסה שלך. הגרסה שנדחית נשארת זמינה בהיסטוריה.

## אבטחה

- סיסמאות נשמרות כ-PBKDF2-SHA256 עם salt אקראי לכל משתמש. מספר החזרות נשמר בתוך
  כל גיבוב, כך שאפשר להעלות אותו בעתיד בלי לשבור סיסמאות קיימות.
- ברירת המחדל היא 20,000 חזרות — נבחרה כדי להישאר בתוך מגבלת ה-CPU של התוכנית
  החינמית (10ms לבקשה). בתוכנית בתשלום אפשר להעלות את `PBKDF2_ITERATIONS` ל-100,000.
- הפעלות נשמרות כעוגייה `HttpOnly; Secure; SameSite=Lax`; בשרת נשמר רק גיבוב הטוקן.
- נעילה של 15 דקות אחרי 8 ניסיונות כניסה כושלים.
- החלפת סיסמה או חסימת משתמש מנתקות מיד את כל המכשירים שלו.
- הרשאת "צפייה בלבד" נאכפת גם בשרת, לא רק בממשק.
